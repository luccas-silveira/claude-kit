# Plano — espelho do Claude Code

Objetivo: o `claude-kit` passa a ser o espelho do Claude Code da máquina de origem — um
comando publica o estado daqui, outro deixa qualquer Mac idêntico, sem sobras e sem faltas.

Spec: `~/Code/claude-tooling/docs/vesta/specs/2026-09-25-espelho-claude-design.md` (repositório
privado local; as decisões dela estão resumidas abaixo onde cada etapa precisa).

Comando de teste (da raiz do kit): `python3 -m unittest discover -s test -v`

Pastas de tela: nenhuma.

## Convenções que valem para todas as etapas

- Código: um módulo só, `espelho.py`, Python da stdlib, compatível com Python 3.9 (é o
  `/usr/bin/python3` de um Mac novo). Subcomandos `sync` e `instalar`. `sync.sh` e
  `install.sh` são só `exec python3 "$(dirname "$0")/espelho.py" sync|instalar "$@"`.
- O home de origem nunca é fixo no código: `espelho.py` usa `Path.home()`, e os testes trocam
  `HOME` por uma pasta temporária.
- Marcador de home: todo texto copiado para `espelho/` troca o home de origem por `__HOME__`;
  o instalador faz o inverso com o home local. Só arquivos de texto (UTF-8 decodificável);
  binário vai intacto.
- Comandos externos (`claude`, `brew`, `npm`, `uv`, `git`, `go`, `docker`, `curl`) passam por
  uma função única `rodar(cmd)` que usa o PATH. Os testes põem na frente do PATH uma pasta de
  stubs: cada stub anexa `nome args` numa linha de `$STUB_LOG` e responde com o conteúdo de
  `$STUB_DIR/<nome>.out` se existir.
- Modelo de teste: `unittest` + `tempfile` + `subprocess`, como
  `~/.claude/skills/vesta/scripts/test_vesta.py:4-37` (ambiente próprio, variáveis `GIT_*`
  removidas).
- Arquivos curados, versionados no kit: `fontes.json` com `programas`, `repositorios` e
  `credenciais` (formato na etapa 1). O manifesto gerado é `manifesto.json`.

## Etapa 0 — Esqueleto de teste e kit antigo removido

- Tela: não
- Arquivos: remover `plugins/`, `.claude-plugin/`, `home/`; reescrever `install.sh`; criar
  `sync.sh`, `espelho.py`, `test/__init__.py`, `test/base.py`, `test/test_cli.py`.
- O que prova a etapa:
  - `python3 espelho.py` sem argumento sai com código 2 e imprime o uso com `sync` e
    `instalar`.
  - `bash install.sh` e `bash sync.sh`, num PATH sem `claude`, repassam para o `espelho.py`
    (o `instalar` recusa com mensagem citando o Claude Code e código diferente de zero).
- Como fazer: `test/base.py` tem a classe `Caso(unittest.TestCase)` com `setUp` criando
  `self.home` (HOME falso), `self.stubs` (pasta de stubs no PATH), `self.log` (STUB_LOG) e o
  helper `self.roda(*args)` que executa `espelho.py` com esse ambiente e devolve
  `(codigo, saida)`. Helper `self.stub(nome, saida='')` cria o stub descrito nas convenções.
  `espelho.py`: `main(argv)` com `argparse`; `instalar` checa `shutil.which('claude')` antes
  de tudo.

## Etapa 1 — Sync copia os arquivos e gera o manifesto

- Tela: não
- Arquivos: `espelho.py`, `fontes.json`, `test/test_sync.py`.
- O que prova a etapa (tudo sobre um HOME falso montado no teste; o sync escreve num kit
  temporário passado por `--kit`):
  - Arquivos gerenciados vão para `espelho/` com o mesmo caminho relativo ao home:
    `.claude/settings.json`, `.claude/settings.local.json`, `.claude/keybindings.json` (se
    existir), `.claude/statusline.sh`, `.claude/skill-stats.py`, as pastas `.claude/skills`,
    `.claude/skills-disabled`, `.claude/agents`, `.claude/commands`, `.claude/output-styles`,
    `.claude/hooks`, `.claude/helpers`, `.claude/plugins/local`, os arquivos
    `.claude/plugins/config.json` e `.claude/plugins/blocklist.json`, `.mcp.json`, e de
    `.config`: `deja`, `caveman`, `yt-dlp`.
  - Nunca entram: `.claude/CLAUDE.md`, `.claude/memory`, `.claude/skills/synced`,
    `__pycache__`, `.DS_Store`, `node_modules`, `.git`, e arquivo listado em
    `fontes.json:credenciais` (ex.: `.config/watch/.env` fora mesmo se a pasta entrasse).
  - Sobra: arquivo que existia em `espelho/` e sumiu do HOME some do `espelho/`.
  - Link simbólico para fora vira cópia real do alvo; link cujo alvo está dentro de um
    repositório de `fontes.json:repositorios` fica como link, com o alvo em `__HOME__`.
  - Texto com o home troca por `__HOME__`; binário sai byte a byte igual.
  - `espelho/mcp.json` tem `global` (de `mcpServers` do `~/.claude.json`) e `porProjeto`
    (chaves de `projects` com `mcpServers`, chave também com `__HOME__`); nenhuma outra
    chave do `~/.claude.json` aparece.
  - `manifesto.json` tem `plugins` (de `installed_plugins.json`: id, versão, ligado conforme
    `enabledPlugins`), `marketplaces` (de `known_marketplaces.json`: nome e fonte),
    `programas` (cada item de `fontes.json:programas` com a versão local, ou `null` se
    ausente), `repositorios` (caminho com `__HOME__`, remote lido por
    `git -C <caminho> remote get-url origin`) e `credenciais` (os caminhos, sem conteúdo).
  - Repositório de `fontes.json` sem remote não entra no manifesto e o sync imprime aviso
    com o caminho.
  - Rodar o sync duas vezes sem mudança no HOME não altera nenhum arquivo do kit.
- Como fazer: a extração de MCP segue `~/Code/claude-tooling/backup/sync.sh:33-41`. Cópia com
  espelhamento: função `espelhar(origem, destino, excluir)` que apaga o destino e recopia,
  com `shutil.copytree(symlinks=True, ignore=...)` e tratamento próprio dos links (resolve
  com `os.path.realpath`). `fontes.json`, formato:
  `{"programas": [{"nome": "jq", "versao": "jq --version", "instalar": "brew install jq"}],
  "repositorios": [{"caminho": "~/Desktop/ZOI/Projetos_ZOI/automaster_v2", "depois": ""}],
  "credenciais": ["~/.config/zoi", "~/.config/watch/.env"]}`. Conteúdo inicial real:
  programas node, python@3.13, uv, jq, gh, go, ffmpeg, yt-dlp (brew); graft (npm
  `@nanonets/graft`); deja (script oficial `curl -fsSL
  https://raw.githubusercontent.com/vshulcz/deja-vu/main/install.sh | sh`); headroom-ai e
  scrapling (uv tool); docker, supacode (brew cask); knobler (`brew install --cask
  luccas-silveira/knobler/knobler`); claude (versão por `claude --version`, instalar pelo
  script oficial). Repositórios: automaster_v2, `~/Code/whatsapp-mcp` (depois:
  `cd whatsapp-bridge && go build`), `~/claude-code-otel` (depois: `docker compose up -d`),
  `~/Documents/2. ZOI/ghl-docs`, `~/Code/claude-tooling`. Credenciais: `~/.config/zoi`,
  `~/.config/watch/.env`, `~/.config/gh/hosts.yml`,
  `~/Code/whatsapp-mcp/whatsapp-bridge/store`, `~/.automaster/chrome-profile`.

## Etapa 2 — Barreiras de segredo e de cliente

- Tela: não
- Arquivos: `espelho.py`, `test/test_barreiras.py`.
- O que prova a etapa:
  - Sync com um arquivo gerenciado contendo `ghp_` + 36 caracteres, `sk-` + 40, um JWT
    (`eyJ…​.eyJ…​.…`), `-----BEGIN … PRIVATE KEY-----` ou `api_key = "<32 caracteres>"` sai
    com código diferente de zero, imprime caminho e linha, e não escreve nada no kit.
  - Sync com um termo de `~/.config/claude-kit/bloqueio.txt` (um por linha, comparação sem
    diferenciar maiúsculas) num arquivo gerenciado ou no manifesto faz o mesmo.
  - Sem `bloqueio.txt`, o sync recusa e diz onde criar o arquivo.
  - Texto limpo passa.
- Como fazer: as barreiras rodam sobre a árvore montada numa pasta temporária, antes de ela
  substituir `espelho/`; se barrar, a temporária é descartada. Regex de segredo parte de
  `~/Code/claude-tooling/backup/sync.sh:50-54` e ganha os quatro padrões acima.

## Etapa 3 — Publicação com confirmação

- Tela: não
- Arquivos: `espelho.py`, `test/test_publicar.py`.
- O que prova a etapa (kit temporário é um repositório git com remote apontando para um
  repositório bare local):
  - Depois de copiar, o sync imprime `git status --short` e `git diff --stat` do kit e
    pergunta `Publicar? [s/N]`.
  - Resposta vazia ou `n`: nenhum commit novo, remote igual.
  - Resposta `s`: um commit com mensagem `espelho: <data ISO>` e o push chega ao bare.
  - Sem mudança: imprime `nada mudou` e não pergunta.
  - `--sim` pula a pergunta (para os testes e para uso consciente).
- Como fazer: `input()` para a pergunta; `git add -A espelho manifesto.json`, `git commit`,
  `git push`. Falha de push sai com código diferente de zero e mostra a linha de erro do git.

## Etapa 4 — Instalador: arquivos e MCP

- Tela: não
- Arquivos: `espelho.py`, `test/test_instalar_arquivos.py`.
- O que prova a etapa (kit de teste com `espelho/` e `manifesto.json` montados no teste,
  HOME falso já com conteúdo, stub `claude` presente):
  - Antes de escrever, cria `~/claude-espelho-<AAAAMMDD-HHMMSS>.tar.gz` com os caminhos
    gerenciados que existiam; a última linha da saída cita o caminho.
  - Cada caminho gerenciado fica idêntico ao `espelho/` com `__HOME__` trocado pelo HOME
    falso; pasta gerenciada perde o que não está no espelho (ex.: skill extra apagada).
  - Intocados: `.claude/CLAUDE.md`, `.claude/memory`, `.claude/skills/synced`,
    `.claude/projects`, e as credenciais existentes.
  - `~/.claude.json`: `mcpServers` e `projects.*.mcpServers` iguais ao espelho (servidor
    extra sai), todas as outras chaves preservadas; arquivo ausente é criado.
  - Link preservado no espelho vira link no destino, apontando para o caminho com o home
    local.
  - Segunda execução deixa todos os arquivos iguais à primeira (exceto o novo `.tar.gz`).
- Como fazer: snapshot e troca de MCP seguem `~/Code/claude-tooling/backup/restore.sh:22-34`
  e `:87-105` (modo `--reset`), com a troca de `__HOME__` também nas chaves de `projects`.
  Espelhamento com a mesma `espelhar()` da etapa 1, no sentido inverso.

## Etapa 5 — Instalador: plugins e marketplaces

- Tela: não
- Arquivos: `espelho.py`, `test/test_instalar_plugins.py`.
- O que prova a etapa (stub `claude` com `plugin list --json` e `plugin marketplace list
  --json` respondendo fixtures):
  - Chama `claude plugin marketplace add anthropics/claude-plugins-official`.
  - Plugin instalado que não está no manifesto: `claude plugin uninstall <id>`.
  - Marketplace instalado que não está no manifesto: `claude plugin marketplace remove
    <nome>`.
  - Plugin do manifesto: nada é chamado para instalar (o settings copiado cuida disso na
    primeira sessão); o relatório final diz que eles se instalam ao abrir o Claude Code.
  - Falha de um comando (stub sai com 1) não para o instalador e aparece na lista final de
    falhas.
- Como fazer: `plugin list --json` traz `id`; `marketplace list --json` traz `name`
  (formatos confirmados em `claude plugin list --help`, Claude Code 2.1.282). Não copiar
  `installed_plugins.json` nem `known_marketplaces.json` para o destino (caminhos absolutos
  de cache; motivo em `~/Code/claude-tooling/backup/README.md:99-102`).

## Etapa 6 — Instalador: repositórios, programas e relatório final

- Tela: não
- Arquivos: `espelho.py`, `test/test_instalar_resto.py`.
- O que prova a etapa (stubs para `git`, `brew`, `npm`, `uv`, `curl`, `sh`, `go`, `docker`):
  - Repositório ausente: `git clone <remote> <caminho com home local>`, depois o comando
    `depois` rodando dentro dele. Repositório já presente: nada.
  - Programa ausente (`versao` falha): roda o `instalar` dele. Presente com versão
    diferente da do manifesto: não reinstala, e o relatório lista "versão diferente: nome
    daqui → de lá".
  - Programa ou clone que falha entra na lista de falhas; o resto segue.
  - Relatório final, nesta ordem: falhas; versões diferentes; credenciais do manifesto que
    não existem no HOME (só o caminho); lembretes fixos (login por QR do WhatsApp e iniciar a
    ponte; abrir o Claude Code para os plugins se instalarem).
  - Código de saída 0 mesmo com falhas listadas; diferente de zero só para recusa inicial.
- Como fazer: tudo por `rodar()`, que devolve `(codigo, saida)`; `shell=True` só para os
  comandos vindos de `fontes.json`/manifesto (são texto curado do próprio kit).

## Etapa 7 — Preparação desta máquina e primeiro espelho real

- Tela: não
- Arquivos: `bloqueio.txt` local (fora do kit), `espelho/`, `manifesto.json`, `README.md`,
  `test/test_espelho_real.py`. Fora do kit: limpeza em `~/.claude`, fork e repositório
  privado no GitHub.
- O que prova a etapa (testes sobre o conteúdo commitado do kit, sem ler o HOME real):
  - `espelho/` não contém: `.claude/skills-disabled/gsd-*`,
    `.claude/hooks/knobler-agent-notify.sh`, `.claude/statusline-command.sh`,
    `.claude/statusline-test.sh`, `.claude/hooks/context-mode-cache-heal.mjs`,
    `.claude/skills/wayfinder/SKILL.md.orig`; `settings.json` sem `get contatos`, sem
    `context-mode-cache-heal` e sem `subagentStatusLine`; `settings.local.json` sem
    `ralph-loop` e sem `vesta.py" silenciar`.
  - Nenhum arquivo do `espelho/` contém `/Users/luccassilveira`.
  - `manifesto.json:repositorios` tem o whatsapp-mcp com remote em `luccas-silveira/` e o
    ghl-docs com remote em `luccas-silveira/ghl-docs`; não tem `claude-tooling`.
  - `manifesto.json` não tem nenhum termo do bloqueio (o teste lê os termos de
    `~/.config/claude-kit/bloqueio.txt` se existir; sem o arquivo, o teste é pulado).
- Como fazer, em ordem, mostrando ao usuário cada item antes de apagar:
  1. `tar -czf ~/claude-antes-limpeza-<data>.tar.gz` de `~/.claude/settings.json`,
     `settings.local.json`, `hooks`, `skills-disabled`, `skills/wayfinder`, `plugins/cache`,
     `plugins/data`.
  2. Remover: permissões com `get contatos` (`settings.json`) e `ralph-loop`
     (`settings.local.json`); o Stop `vesta.py" silenciar` de `settings.local.json`;
     `subagentStatusLine`; o hook `context-mode-cache-heal.mjs` e seu registro; as 66
     `skills-disabled/gsd-*`; `knobler-agent-notify.sh`, `statusline-command.sh`,
     `statusline-test.sh`; restos de `claude-mem` em `plugins/cache/thedotmack` e
     `plugins/data/claude-mem-thedotmack`; `skills/wayfinder/SKILL.md.orig`; os dois caminhos
     inexistentes de `skills/ghl-api-docs/SKILL.md` (linha 29 passa a
     `~/.claude/skills/ghl-api-docs/docs`; linha 38 sai).
  3. `gh repo fork lharries/whatsapp-mcp --clone=false`, depois tornar privado (`gh repo edit
     --visibility private`; se o GitHub recusar fork privado, criar
     `luccas-silveira/whatsapp-mcp` privado e dar push). Em `~/Code/whatsapp-mcp`: commit das
     alterações locais, `origin` para o repositório novo, `upstream` para o original, push.
     `whatsapp-bridge/store` continua ignorado pelo git.
  4. `gh repo create luccas-silveira/ghl-docs --private --source "~/Documents/2. ZOI/ghl-docs"
     --push`.
  5. Criar `~/.config/claude-kit/bloqueio.txt` com a lista aprovada na spec.
  6. `bash sync.sh`, revisar o resumo com o usuário, publicar.
  7. README: o que é o espelho, os dois comandos, o que fica fora (CLAUDE.md, memória,
     credenciais), o que continua manual (credenciais, login do Claude, QR do WhatsApp,
     `graft init` por repositório), como desfazer (o `.tar.gz`).
